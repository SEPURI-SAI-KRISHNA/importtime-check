# importtime-check 0.2.0a1

This first 0.2 alpha adds offline, descriptive analysis of complete version-1
measurement reports. It can summarize repeated observations and compare
before/after cohorts without importing targets again or turning an observed
shift into an approved regression budget. The public API is still prerelease.

## What's new

- `load_measurement_report` and `decode_measurement_report` strictly read the
  v1 `measurement` JSON produced since `0.1.0a4`. They reject malformed,
  duplicate-key, oversized, and unsupported-version input. Each loaded
  report retains a SHA-256 digest of its exact source bytes for review.
- `summarize_measurement_reports` and `report summarize` accept 2–64 complete
  reports from an asserted comparable runner and installation context. For
  each target they show the observed upper median of run medians, range, and
  spread. Source digests and target order are deterministic; no run is
  silently omitted or merged into pooled child samples.
- `compare_report_cohorts` and `report compare` show signed microsecond and
  percentage changes, both complete cohort summaries, and each side's
  spread. Reported environment, sampling, runner context, and target set
  must match across sides; installation labels may differ for the intended
  change. A zero before median has no defined percentage.
- Summary and comparison JSON use separate `analysis_type` values and
  `analysis_version: 1`. Neither document is a measurement report, a
  baseline, a `check` result, or a regression verdict. Expected invalid
  input exits the CLI with code `2` and empty stdout; normal diagnostics
  avoid report contents and private file paths.
- Archived v1 fixture bytes now exercise loading, summarizing, comparing,
  and rejecting future versions in CI. Selected Windows and macOS lanes
  additionally build and smoke-test the installed wheel's report path; the
  required aggregate `CI` result includes those lanes.

After publication, install the exact prerelease:

```console
python -m pip install --pre importtime-check==0.2.0a1
python -m pip install --pre "importtime-check[pytest]==0.2.0a1"
```

Before publication, the PyPI pin cannot resolve; use a clean wheel built
from the reviewed source. To analyze previously collected v1 files without
new target imports:

```console
importtime-check report summarize --file before-1.json --file before-2.json --runner-context ubuntu24-py311 --install-context build-before
importtime-check report compare --before-file before-1.json --before-file before-2.json --after-file after-1.json --after-file after-2.json --runner-context ubuntu24-py311 --before-install-context build-before --after-install-context build-after
```

Add `--format json` for independently versioned, machine-readable analysis.
These are examples of input shape, not bundled report files. Preserve the
original files and the actual runner, dependency lock, Python patch level,
and installed revisions alongside their digests. Equal safe identity fields
or caller-supplied context labels cannot prove equal hardware, load, or
dependencies. Read spreads and investigate outliers before interpreting a
shift; the commands do not select allowances or update baselines.

## Upgrade and compatibility

The Python floor remains 3.11, with CPython 3.11–3.14 in the tested matrix.
The core still has no runtime dependencies; pytest integration remains an
explicit optional extra. Existing `measure`, `baseline record/show/refresh`,
`check`, and explicit pytest-plugin behavior remain available. Baseline and
check schemas remain version 1; no baseline migration is needed. The v1
measurement report shape emitted by `0.1.0a4` remains readable. The new
analysis documents cannot be passed to `check` as baseline policy.

To upgrade a consuming project, deliberately change its exact tool pin to
`0.2.0a1` after publication and retain its existing reviewed baseline.
Use the [measurement artifact guide](../guides/measurement-artifacts.md) to
collect and review complete reports, then the separate
[CI baseline guide](../guides/ci-baselines.md) if a human-reviewed budget is
ready. The pinned example workflows are templates for a consuming project,
not automatic changes to this repository's release pipeline.
