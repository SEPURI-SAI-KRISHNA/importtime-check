# importtime-check 0.1.0a4

This fourth alpha adds standalone multi-target import measurements. You can
collect observations for several installed modules through the Python API or
as a reviewable CLI JSON report, without recording or changing a regression
baseline. The public API remains prerelease and may change before 1.0.

## What's new

- `sample_imports` samples a non-empty set of distinct module names in sorted
  order. Each warmup and recorded sample runs in a fresh isolated child. It
  returns a complete tuple only if every target succeeds; errors identify the
  failing target, phase, and one-based run number.
- `importtime-check measure` accepts repeated `--module` options. Default
  text output repeats the established three-line block per target; the old
  one-module text output is unchanged. `--format json` produces a separate
  `report_type: "measurement"`, `report_version: 1` document with ordered
  warmup and sample arrays, observed upper medians, and safe interpreter
  identity. A failed measurement exits `2` without a partial stdout report.
- The [measurement artifact guide](https://github.com/SEPURI-SAI-KRISHNA/importtime-check/blob/main/docs/guides/measurement-artifacts.md)
  and pinned manual consuming-project workflow show how to collect a
  two-module JSON artifact for human review. Uploading an observation never
  approves a budget or rewrites a baseline.

After installing the release, try two installed standard-library targets:

```console
importtime-check measure --module email --module json --warmups 1 --samples 5
importtime-check measure --module email --module json --warmups 1 --samples 5 --format json
```

The library equivalent is:

```python
from importtime_check import sample_imports

for result in sample_imports(("json", "email"), warmups=1, samples=5):
    print(result.module, result.median_cumulative_us)
```

Target order is `email`, then `json`, regardless of caller order. Reported
microseconds are CPython's target cumulative import-time diagnostics, not
whole-process startup time or a regression verdict. Compare repeated complete
reports only in a controlled, comparable environment; even matching report
identity omits Python patch level, dependencies, runner load, and hardware.

## Install and upgrade

After publication, install the exact prerelease, adding the optional pytest
extra only when needed:

```console
python -m pip install --pre importtime-check==0.1.0a4
python -m pip install --pre "importtime-check[pytest]==0.1.0a4"
```

Upgrade exact pins in consuming-project lock files deliberately. The core
package still has no runtime dependencies, and pytest integration is opt-in;
it is not loaded automatically. Python 3.11 is the minimum, with CPython
3.11 through 3.14 in the tested matrix. Existing one-module measurement
calls, common-allowance and per-target baseline recording, `baseline refresh`,
`check`, and explicit pytest integration retain their behavior.
Baseline JSON and check reports remain `schema_version: 1`; no baseline
migration is needed. The new measurement report uses its own `report_version`
and is **not** a baseline input or an approved policy file. `check` and pytest
neither learn nor refresh budgets from it.

## Review and limits

For a CI artifact, use the pinned, manual
[observation workflow](https://github.com/SEPURI-SAI-KRISHNA/importtime-check/blob/main/docs/examples/collect-importtime-measurement.yml).
For a reviewed regression gate, follow the separate
[baseline guide](https://github.com/SEPURI-SAI-KRISHNA/importtime-check/blob/main/docs/guides/ci-baselines.md).
The example targets and allowances are illustrative, not universal
performance thresholds. Host load, interpreter and dependency changes, and
runner differences can affect timing; a single report cannot establish a
sound budget.

See the [README](https://github.com/SEPURI-SAI-KRISHNA/importtime-check/blob/main/README.md)
for API and CLI examples and the
[release process](https://github.com/SEPURI-SAI-KRISHNA/importtime-check/blob/main/docs/releases/README.md)
for publication and verification. Security reports use
[private vulnerability reporting](https://github.com/SEPURI-SAI-KRISHNA/importtime-check/blob/main/SECURITY.md).
