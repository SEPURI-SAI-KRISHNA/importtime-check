# importtime-check 0.1.0a2

This second alpha adds a safer way to maintain reviewed import-time baselines
and clearer explanations when a comparison cannot be made. It remains a
prerelease: the public API and reporting details may change before 1.0.

## What's new

- `importtime-check baseline refresh --file PATH --replace` remeasures the
  existing targets and updates their observed medians without changing their
  approved allowances, sampling policy, or environment identity. Refresh is
  explicit; neither `check` nor the pytest plugin performs it automatically.
- The public `refresh_baseline(baseline, observations, environment)` API returns
  an updated baseline without writing it. Saving still requires an explicit
  `save_baseline(..., replace=True)` call.
- Baseline mismatch diagnostics identify differing environment fields and
  sorted missing or stale target names. They avoid exposing private paths and
  full interpreter-version details in these messages.
- A [CI baseline guide](https://github.com/SEPURI-SAI-KRISHNA/importtime-check/blob/main/docs/guides/ci-baselines.md) supplies a pinned example
  for recording a candidate, reviewing it, and checking a committed baseline
  in a consuming project's GitHub Actions workflow.
- Release preflight now derives the exact open milestone and release issue
  from the source version instead of depending on the first alpha's issue
  numbers. This changes release controls, not the installed package behavior.

## Install and upgrade

After publication, install the exact prerelease and its optional pytest extra
only if you use that integration:

```console
python -m pip install --pre importtime-check==0.1.0a2
python -m pip install --pre "importtime-check[pytest]==0.1.0a2"
```

Upgrade an exact `0.1.0a1` pin deliberately in your project lock file. The
baseline JSON format remains schema 1; existing baselines do not require
migration or automatic refresh. Review any proposed median update as a normal
policy-file diff. A change to targets, environment identity, sampling, or
allowances needs a separately reviewed re-recording or policy edit; refresh
will not make those changes for you.

The core package still has no runtime dependencies. The optional pytest
integration remains opt-in and is not auto-loaded. No new runtime dependency
or interpreter minimum is introduced by this release.

## Compatibility and limits

CPython 3.11 through 3.14 are tested; metadata permits Python 3.11 or newer,
but later versions are outside the tested matrix. CLI check exit codes remain
`0` for pass, `1` for regression, and `2` for invalid input or operational
failure. The machine-readable check report remains schema 1. `BaselineError`
adds `differing_fields` for environment mismatch inspection.

Measurements still use fresh isolated CPython processes and report import-time
diagnostics rather than whole-process startup time. Host load, dependency
changes, and runner differences can change results even when baseline identity
matches. Keep comparisons in controlled environments and investigate observed
variance before changing a reviewed budget.
